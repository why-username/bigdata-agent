# 扩展研究数据 88 条 Qwen API 实验：优化前后报告

## 实验状态

阶段 5 已完成。两次运行均使用同一批 88 条最新截点任务、同一数据快照、并发 1 和相同模型预算。原始结果保存在 `outputs/evaluations/eval-research_api-88-resumable.json`，优化结果保存在 `outputs/evaluations/eval-research_api-88-optimized.json`。

## 优化内容

1. 将模型常用的 `before` 日期条件归一化为工具规范的 `received_to`，避免合法的截点条件被工具拒绝。
2. 对模型输出增加 JSON 片段提取：允许前后有说明文字或 Markdown 包裹，同时仍要求最终动作通过严格的 `tool_call`/`done` 校验。
3. 优化版使用独立断点文件，未覆盖基线。

## 结果对比

| 指标 | 基线 | 优化版 |
|---|---:|---:|
| 任务数 | 88 | 88 |
| 自动通过（passed） | 88 | 88 |
| completed | 81 | 79 |
| needs_human_review | 7 | 9 |
| Agent 自动分数均值（5分） | 3.170 | 3.193 |
| 固定流程均值 | 3.125 | 3.125 |
| 普通 RAG 均值 | 2.125 | 2.125 |
| ReAct 基线均值 | 3.250 | 3.250 |
| 平均延迟 | 50.49 秒 | 50.33 秒 |
| 平均 token | 24,701 | 24,830 |

Agent 分数提高约 0.023 分，延迟基本不变。相对于普通 RAG，Agent 高 1.068 分；相对于固定流程，高 0.068 分；相对于本实验中的 ReAct 基线，低 0.057 分。因此不能宣称 Agent 在全部指标上胜出。

## 错误分析

基线出现了 1 次 `before` 未声明字段、11 次无效 JSON、9 次非法动作类型。优化后 `before` 错误归零，无效 JSON 错误仍被重试机制记录 11 次，非法动作类型记录 12 次；这些错误均未导致 `passed=false`，但部分任务因计划没有完全闭合而进入 `needs_human_review`。这说明协议适配已改善，但模型动作格式的约束仍会产生重试开销，不能把“通过”解释为每一步都无错误。

## 结论与限制

本次结果验证了在扩展数据和严格截点条件下，Agent 工程闭环可以稳定完成 88 条任务，并能将模型协议错误限制在有界重试内。证据覆盖、引用可核验性和基线分数由相同确定性工具计算。自动分数是流程指标，不等同于真实调查质量；仍需在论文级报告中单独呈现 needs_human_review 案例、反证发现和补查建议的人工复核结果。当前 API 实验没有证明 Agent 优于所有基线，最稳妥的结论是：Agent 相比普通 RAG 有明显流程收益，相比固定流程只有轻微收益，相比 ReAct 基线略低。
