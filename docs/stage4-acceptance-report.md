## 三种运行方式

固定流程执行筛选、趋势、证据和实体关联；普通 RAG 只执行证据检索；主动调查 Agent 依据目标运行受限循环。三者使用相同案例快照、案例截点和本地证据索引。评测记录调用次数、唯一证据文档数、关联去重投诉数、耗时、Agent token 数和模型成本字段。离线模式 token 为 0，成本为 null；API 模式未运行。

当前结果中三种方式可能命中相同的证据文档。这是因为它们共享同一证据索引和元数据查询，不能据此断言质量相同或 Agent 胜出。建议质量、反证发现和补查质量必须按人工 0–2 分评分：0=未提出可执行且有依据的建议；1=部分相关但缺少关键依据或验收条件；2=针对当前证据缺口提出具体、可验证、带停止条件的下一步核查。

## 事实引用与边界

每个 Agent 状态保存计划、工具轨迹、确定性验证、证据台账、来源记录编号、竞争性假设和事实主张。报告只展示通过验证的工具观察；事实主张绑定工具结果步骤及来源 ID。缺少来源、超过截点、来源冲突或留出材料不会作为已核验事实。证据立场受控为 `support`、`oppose`、`neutral`、`needs_review`，没有依据的立场自动降级为 `needs_review`。

## AI 协作与纠错要点

1. 发现三种方法证据数都为 1 后，检查统计口径，区分证据文档数和其关联的 528 条原始投诉，避免把索引文档数误报为数据量。
2. 发现中文查询与英文 NHTSA 材料词面不一致后，改用官方品牌、车型和部件字段，并增加样本证据的英文检索词。
3. 发现 `citation_valid` 原检查只是“证据 ID 是否在自身列表”，改为检查来源定位、发布日期、原始投诉编号存在性和截点边界。
4. 发现计划虽保存但验证失败后没有真正重查，加入受控重规划动作、重复动作停止和两次重规划上限。
5. 发现迁移案召回总量不等于截点前可用量后，按接收日期重算，并把官方调查全量表和候选替代案例单独保存，未擅自替换主案。
