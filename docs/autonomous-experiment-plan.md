# 主动调查 Agent 自动化实验方案

原来的 15 条任务是最低验收集，且把建议质量留给人工 0–2 分，不能独立回答 Agent 是否优于基线。快速回归套件保留 24 条冻结任务：12 条主案任务（6 个目标各覆盖原始截点和较早/中间截点变体）、2 条迁移任务、10 条异常/边界/反馈任务。研究套件由 `scripts/build_research_benchmark.py` 生成 264 条任务：11 个公开案例 × 8 个目标 × 3 个历史截点；`research_api` 子集固定取 11 个案例的最新截点，共 88 条代表任务。

每个任务预先声明期望工具和边界，自动评分不读取模型自由文本，也不使用人工语义判断：

1. `plan_execution`：期望的前两个工具是否实际成功且通过验证；
2. `evidence_traceability`：是否有截点内、带来源定位的证据台账；
3. `counterevidence_action`：反证任务是否实际调用证据检索；
4. `followup_action`：补查任务是否实际生成；
5. `bounded_stop`：是否保存完成/人工复核/最大轮数等停止状态。

每项 0/1 分，总分 5 分。固定流程、普通 RAG、ReAct 和主动信息增益 Agent 使用同一案例、同一截点和同一证据索引，并记录各自自动分数、工具调用数、证据文档数、关联投诉数、耗时、token 和成本字段。分数衡量可审计行为，不宣称语义结论正确；未来可以用留出答案构造额外的事实级自动指标。研究套件同时输出均值、样本标准差和固定随机种子的 bootstrap 95% 区间。

最新研究级离线结果：`outputs/evaluations/eval-research-20261101-000348.json`，264/264 通过；快速回归结果：`outputs/evaluations/eval-fast-20261031-230229.json`，24/24 通过。主动信息增益首轮与 ReAct 的自动行为分数相同，因此只能说明工程流程稳定和轨迹可审计，不能据此宣称语义调查质量已经提升。

API 实验仍应在并发 1 下运行；API 返回的动作先经过同一白名单、参数、截点和来源验证，失败必须计入失败清单。模型 token 和推理耗时属于成本指标，不是质量分。
