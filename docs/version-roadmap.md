# V1–V4 任务迭代与最终使用方式

| 版本 | 主要任务 | 新增能力 | 结果定位 |
|---|---|---|---|
| V1 | 先跑通车辆投诉调查 Agent | 五个本地工具、计划执行、状态 JSON、JSONL 日志、来源和截点校验 | 工程闭环起点；后来扩展为88条真实 Qwen 主实验 |
| V2 | 修复数据和协议问题 | NHTSA车型名称映射、统一工具参数、有限重试、错误记录、迁移案例和研究数据包 | 数据质量与工具契约稳定化 |
| V3 | 让 Agent 的动态性可观察 | 六类动态状态：空结果、来源冲突、竞争假设、证据充分、截点泄漏、补查缺口；加入反证和补查行为指标 | 24条真实 Qwen 动态 pilot，暴露模型失败模式 |
| V4 | 做四方法统一对照 | 固定流程、普通 RAG、确定性工具循环、主动 Agent；显式安全门、证据图、状态分支、有限重规划 | 24条真实 Qwen pilot + 24条离线统一对照 |
| V4后反馈扩展 | 测试新证据到达后的更新 | 结案后不完整反馈、结论更新、不确定性保留和补查建议评分 | 4案探索性结果；不作为主实验结论 |

## 最终报告中的数据分层

1. **主实验：88条 Qwen API 任务**。用于报告四种策略在扩展案例上的流程行为和成本结果。
2. **动态补充：V4 24条 Qwen API 任务**。用于说明 Agent 能在部分动态状态下改变首步动作，并暴露需要安全门纠偏的场景。
3. **工程验证：264条离线任务**。用于证明数据、工具、状态、日志、证据图和边界检查可复现。
4. **探索性附录：4案反馈后实验**。用于展示结案后不完整反馈的更新过程，不用于宣称普遍性能优势。

## 不能混淆的指标

结构性通过率表示来源、日期、截点、参数和状态格式检查通过，不表示调查结论正确。安全门纠偏表示系统阻止了越界动作，不表示模型自主完成了该动作。工具调用数、延迟和 token 是成本诊断，不是 Agent 质量分。

## 展示时的建议顺序

先用离线 Demo 展示一条主案调查轨迹，再展示补查反馈后续跑；随后用一页表格说明88条 Qwen 主实验，最后用V4动态结果解释 Agent 的价值和限制。没有 Qwen API 时，Demo 仍能用本地公开快照和离线策略完整运行。
