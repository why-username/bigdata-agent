# 项目说明文档与 PPT 架构 V2

## 项目说明文档

### 1. 问题和用户

说明车企安全调查员面对多渠道投诉、维修、现场事件、工程文档和监管信息时，手工汇总慢、来源难追溯、容易只找支持证据。定义目标用户、调查边界和最终决策责任。

### 2. 用户工作流

用一个完整案例说明：异常触发、分诊、自动数据汇总、假设竞争、主动核查、风险分流、审批、反馈再运行和结案归档。

### 3. 数据和企业连接

说明公开数据用于研究回放，企业数据用模拟适配器展示。列出投诉、保修维修、车辆配置、现场事件、工程文档、监管公开资料和调查工作流的统一接口、字段来源和权限边界。

### 4. Agent 架构

展示 Plan-and-Execute 主循环、工具选择、证据图、状态/记忆、验证器、有限重规划、安全门和审批层。说明 Agent 只生成调查建议和结构化任务草稿，不自动作出最终安全缺陷认定。

### 5. 调查决策机制

解释 Agent 如何根据证据缺口选择下一数据源，如何维护支持/反对/中性/待确认证据，如何更新竞争性假设，如何决定继续、补查、升级或停止。

### 6. 实验设计

把实验分成三层：88条真实 Qwen 主实验、V4 24条动态 API 补充、264条离线工程验证。说明四种方案和指标边界。

### 7. 结果与限制

主实验报告 Agent、固定流程、普通 RAG 和确定性 ReAct 的流程分；V4 报告动态场景动作和安全门纠偏；离线结果只报告工程闭环。明确 Agent 尚未证明优于所有基线，也不替代最终工程鉴定。

### 8. Demo 使用说明

给出启动命令、案例选择、调查目标、查看下一步动作、查看证据图、审批任务草稿、输入模拟反馈和下载报告的步骤。

### 9. 企业部署路线

说明从本地模拟适配器迁移到企业 API 的方式，以及 SSO/RBAC、数据脱敏、审计、人工审批、只读与写入分级和模型降级要求。

### 10. 复现和 AI 协作记录

列出代码、数据快照、评测 JSON、运行日志、失败样例和至少三条 AI 协作与纠错记录。

## 12页 PPT

### 第1页：标题和一句话价值

“Agent 帮助车企调查员从多源异常信号走到可追溯的下一步核查决策。”

### 第2页：真实调查痛点

展示投诉、维修、VIN 配置、现场事件、工程文档和监管材料分散在不同系统中的问题。

### 第3页：目标用户和完整工作流

用调查员视角展示异常触发 → 自动汇总 → 主动核查 → 审批 → 反馈再运行 → 归档。

### 第4页：问题边界和责任边界

说明公开资料历史回放、企业连接器模拟、Agent 辅助调查、最终结论由授权人员负责。

### 第5页：系统架构

展示数据源适配层、统一证据对象、Agent 循环、验证器、状态记忆、审批工作流和报告层。

### 第6页：Agent 如何做动态调查

用一条轨迹说明当前假设、证据缺口、下一查询、观察结果和假设更新。

### 第7页：证据图和竞争性假设

展示投诉—车型—部件—维修—现场事件—工程文档—监管材料之间的关系，区分支持、反对和待确认。

### 第8页：Demo 截图和使用过程

展示调查队列、工作台、Agent 下一步卡、证据台账、审批任务和反馈后状态变化。不要放四种方案实验表。

### 第9页：Agent 的企业接入方式

展示六类只读适配器和审批型工作流适配器，说明如何从模拟接口迁移到企业 API。

### 第10页：主实验结果

展示88条真实 Qwen API 主实验，明确流程分是工程行为指标，不等于安全缺陷判断准确率。

### 第11页：动态性和工程验证

上半部分展示V4 24条真实动态任务，下半部分展示264条离线工程验证，区分模型自主动作、安全门纠偏和离线回归。

### 第12页：结论和下一步

结论聚焦早期筛查、证据缺口识别、补查决策和不确定性控制；说明限制、企业试点路线、代码仓库和 Demo 使用方式。
