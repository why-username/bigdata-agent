# 车企安全调查员工作台：Demo 重规划

## 产品定位

Demo 模拟车企车辆缺陷安全调查员或质量工程师收到异常信号后的真实工作过程。Agent 是调查辅助层，负责跨来源汇总信息、形成竞争性假设、选择下一步核查、维护证据链和生成调查建议；调查员保留调查立项、风险等级、对外联系和最终结论的审批权。

当前仓库没有车企内部权限，因此 Demo 使用本地脱敏模拟适配器展示企业流程。模拟适配器的接口与真实系统接口保持一致，未来可以替换为企业 API、消息队列或数据库查询。页面和报告必须标注“企业数据为模拟数据”，不宣称已接入任何车企。

## 真实使用场景

一个调查员通常不会从空白文本开始输入证据。流程由质量平台、投诉中心、售后维修系统、车联网事件平台或监管预警触发。Agent 接收一个调查上下文：车型/年款、VIN 范围或零件号、症状、时间范围、地区、已有调查编号和风险等级。

Agent 随后通过受控连接器自动查询企业允许访问的数据源，并把结果统一成带来源、时间、权限和可信状态的证据对象。它根据证据缺口决定下一次查询，调查员在关键节点确认方向或审批需要写入企业系统的动作。

## 企业数据连接层

Demo 将企业内部能力抽象为六类只读适配器和一个审批型动作适配器：

| 适配器 | 真实系统示例 | Demo 模拟内容 | Agent 用途 |
|---|---|---|---|
| `complaint_crm` | 客服/投诉管理平台 | 投诉、症状、地区、时间、VIN 脱敏标识 | 汇总投诉、去重、筛选共同模式 |
| `warranty_repair` | 保修索赔、维修工单、零件更换记录 | 故障码、维修项目、零件号、返修记录 | 验证投诉是否对应实际维修现象 |
| `vehicle_config` | VIN 配置、生产批次、供应商和软件版本 | 车型、年款、批次、零件版本 | 关联车型、批次和零件变更 |
| `field_incident` | 道路救援、事故、车联网异常事件 | 事件时间、严重等级、故障码、位置网格 | 检查是否存在安全相关现场事件 |
| `engineering_docs` | 试验报告、工程变更、服务公告、设计文件 | 文档摘要、版本、发布日期、引用位置 | 检索支持与反证技术材料 |
| `regulatory_public` | NHTSA、监管公告和召回信息 | 本地公开快照 | 关联外部调查、召回和公开证据 |
| `case_workflow` | 质量调查/8D/CAPA/风险评审平台 | 调查单、任务、审批状态 | 保存调查状态和生成待审批动作 |

所有适配器都返回统一结构：`source_system`、`source_record_id`、`case_id`、`observed_at`、`published_at`、`retrieved_at`、`field_provenance`、`access_scope`、`confidence` 和原始查询条件。企业系统中的敏感字段只在连接器内部使用，进入 Agent 上下文前进行脱敏和最小化。

## Agent 如何自动补齐证据

页面中的“补查任务”改成“证据缺口与自动检索计划”。当 Agent 发现只有投诉而没有独立维修或工程材料时，它自动执行以下流程：

1. 从当前案例抽取车型、年款、部件、症状、时间范围、VIN 脱敏集合和已有调查编号。
2. 先查 `warranty_repair`，确认是否存在与症状和部件匹配的维修记录。
3. 再查 `vehicle_config`，确认记录是否集中在某个批次、零件版本或软件版本。
4. 根据风险等级查 `field_incident`，寻找道路事件、故障码或严重度变化。
5. 查 `engineering_docs` 和 `regulatory_public`，寻找支持材料、反证材料和来源冲突。
6. 将结果写入证据台账，更新竞争性假设和证据缺口。
7. 只有在查询权限不足、来源冲突无法消解、需要对外联系或需要写入企业系统时，才生成审批任务给调查员。

人工不需要逐条录入缺失证据。人工操作集中在：确认调查范围、批准升级查询、处理冲突记录、批准创建企业调查任务、审批最终风险建议。

## 调查员的完整使用流程

### 1. 异常触发

调查员从“待分诊队列”打开一个系统生成的案例。页面显示触发来源，例如投诉量异常、维修返修率升高、现场事件、监管材料或工程变更。

### 2. 初始分诊

Agent 自动汇总多源信号，显示：投诉量趋势、维修匹配率、现场事件等级、涉及批次、外部公开证据和数据缺失项。Agent 给出 provisional assessment，并明确“已知、待确认、反证和缺口”。

### 3. 主动调查

调查员看到 Agent 当前准备查询的系统、查询理由、预计验证的假设和验收条件。只读查询自动执行；每次查询结果进入时间线和证据图。

### 4. 假设竞争

Agent 同时维护“共同安全缺陷”“批次或零件版本问题”“维修/使用因素”“文本相似但根因不同”等假设。新证据会改变各假设的状态，但不会把相关性直接写成因果结论。

### 5. 风险分流

Agent 根据证据覆盖、严重度、独立来源和不确定性提出分流建议：继续观察、扩大样本、启动工程核查、升级安全评审或请求人工复核。建议包含依据和停止条件。

### 6. 审批和企业任务

若需要创建 8D、CAPA、工程试验、供应商核查或外部调查任务，页面生成结构化草稿。调查员确认后才写入模拟 `case_workflow`；Demo 中不向真实企业系统发送数据。

### 7. 新反馈再运行

维修结果、工程测试、供应商回复或新的投诉批次进入后，Agent 自动关联到原调查，标记新增证据，重新评估假设，展示前后变化，并说明是否需要升级或关闭。

### 8. 结案归档

系统输出调查摘要、证据台账、假设变化、审批记录、未决风险和完整审计轨迹。最终安全缺陷认定仍由企业授权人员完成。

## Demo 页面结构

### 页面一：调查队列

显示待分诊案例卡片：触发原因、车型、部件、严重度、投诉趋势、维修匹配率、数据完整性和当前负责人。点击案例进入调查工作台。

### 页面二：调查工作台

首屏分成四块：

- **当前判断**：provisional assessment、证据强度和未决问题；
- **数据源状态**：投诉、维修、配置、现场事件、工程文档、监管公开资料的查询状态；
- **Agent 下一步**：将查询哪个系统、为什么查询、验收条件和停止条件；
- **风险分流**：继续收集、工程核查、升级安全评审或人工复核。

### 页面三：证据和假设

用证据台账、竞争性假设卡片和证据图展示每个事实来自哪个企业系统或公开来源。支持、反对、中性和待确认证据用不同颜色表示，冲突来源单独标红。

### 页面四：调查时间线

按时间展示触发、查询、观察、假设更新、重规划、审批和反馈。每一步标注“Agent 自主动作”“规则安全门”“调查员确认”或“系统自动接入”。

### 页面五：审批与企业任务

展示自动生成的工程核查、维修抽样、供应商确认、8D/CAPA 草稿。用户只需要审批或退回，证据不再靠手工逐条录入。所有写入动作在 Demo 中进入模拟工作流并保留审计记录。

### 页面六：结案与回放

展示当前状态、前后假设变化、未决风险、来源清单、审计轨迹和报告下载。四种方法的实验结果移到 PPT 和项目说明，不放入 Demo 主流程；页面只保留一个“查看研究评测摘要”的次级入口。

## 车企接入边界

第一阶段只读接入和本地模拟写入。真实部署时按权限分层：投诉和维修查询可以自动执行；跨部门任务创建、供应商联系、监管报送和召回建议必须经过审批。所有查询和写入都记录用户、时间、系统、参数摘要、返回记录数量和审计 ID。

## Demo 成功标准

五分钟演示必须能展示一条完整链路：异常触发 → 自动汇总多源数据 → Agent 选择下一查询 → 证据改变假设 → 生成工程核查任务草稿 → 调查员审批 → 新反馈进入 → 假设更新 → 输出可追溯摘要。

演示重点是 Agent 如何帮助调查员工作，实验对比数字放入 PPT。没有企业真实接口时，页面必须明确标注模拟连接器和脱敏数据，不将模拟结果描述为企业真实效率。
