# Agent V2 迭代方案：从工具完成到调查决策价值

## 迭代目标

V1 主要回答“Agent 是否完成了规定工具链”。新版改为回答“Agent 是否帮助调查员减少关键不确定性并提出可执行的下一步”。核心比较对象仍包括固定流程、普通 RAG 和 ReAct。

## 面向用户的评价维度

每条任务输出 0–100 的 `decision_value_v3`，由以下四部分组成：

- 安全与可追溯性（30%）：截点无泄漏、来源和记录可回溯、引用可核验。任何未来材料、无来源证据或无法定位的事实主张都会使这一项为 0。
- 目标覆盖（25%）：是否完成当前调查目标所需的最小决策条件。例如趋势任务需要形成时间趋势，反证任务需要检索替代解释，补查任务需要形成可交给人工的任务。工具调用只是实现手段，不是得分对象。
- 证据质量（20%）：独立来源族数量、支持/反对证据是否有区分；重复来源不重复计分。
- 下一步价值（25%）：反证任务是否真正查询替代解释；补查任务是否包含问题、依据、证据 ID 和可验收反馈；普通任务是否能根据当前缺口给出有停止条件的下一步。
- 工具调用数、延迟和 token 不进入质量分，只作为成本诊断单独报告。重复调用只有在造成安全问题或没有完成目标时，才通过安全与目标覆盖间接影响质量。

V1 五分制轨迹分数继续保留，作为兼容指标；新版四维分数作为用户价值主指标。工具调用数、延迟和 token 只用于回答“收益是否值得成本”，不用于提高或降低调查质量分。

## Agent 侧改动

1. API 提示中加入当前候选动作、估计 utility 和动作理由，让模型在候选集合内做主动选择。
2. 加入目标完成门槛：模型输出 `done` 前，`trend` 必须有趋势分析，`counterevidence` 必须执行替代解释检索并完成实体核验，`followup` 必须创建带依据和验收条件的补查任务，其他目标也有对应的最小动作集合。
3. 记录决策价值指标和完成门槛触发轨迹，区分模型自主决策与验证器纠偏。
4. 保持有限循环、截点过滤、来源验证和本地任务边界。

## 研究假设与消融

- H1：加入候选动作和完成门槛后，反证/补查目标的下一步价值提高。
- H2：V2 的 Agent 相比 ReAct 在目标切换时更少使用泛化查询，且不增加重复调用率。
- H3：主动决策带来的证据质量增益能够解释其额外 token 和延迟成本。

至少运行四个版本：ReAct、V1 API、V2 API、V2 去除完成门槛。主结果报告 22 条 pilot 和 88 条最新截点全量结果，并按 focus 分层。若 API 成本或时间受限，先完成 pilot，再重跑受影响 focus 的任务。

## 解释边界

V2 指标是由数据和轨迹确定性计算的行为指标，不是人工语义判断，也不是企业效率证明。证据文档数量、投诉数量和工具调用数量都不直接等于调查质量。报告必须同时列出异常任务、门槛触发次数、模型协议重试和成本。
