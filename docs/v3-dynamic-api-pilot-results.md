# V3 Qwen 动态决策 Pilot

## 运行范围

使用 EA22002、PE20016、PE23015、PE24004 四个候选案例，每案六类动态场景，共 24 条 Qwen API 任务。并发为 1，使用相同截点和候选案例包，结果保存于 `outputs/evaluations/eval-research_v3-dynamic-api.json`。

## 结果

- 24/24 条任务完成处理；23 条通过截点与引用自动检查，1 条因达到最大步数未通过。
- 状态：12 条 `completed`、11 条 `needs_human_review`、1 条 `max_steps_reached`。
- 空结果恢复：首步分支正确率 1.0，平均决策价值 97.5。
- 来源冲突：模型能完成工具链，但首步仍常选择默认投诉筛选，说明冲突状态尚未真正进入动作选择；平均决策价值 97.5。
- 竞争性假设：首步通常选择替代解释检索，但 EA22002 出现连续相似检索并达到最大步数，说明反证后的停止/转向条件不足；平均决策价值 85.0。
- 证据充分停止：模型通常仍开始投诉筛选，首步停止率低；平均决策价值 75.0。
- 截点泄漏：模型会进入人工复核或安全停止，但没有稳定地第一步停止；平均决策价值 87.5。
- 补查缺口：模型能生成内容具体的补查任务，但部分任务先走默认搜索，平均决策价值 55.0。

## 主要结论

V3 已经把动态优势变成了可观察的行为差异：模型在竞争性假设任务中会使用替代解释检索，在补查任务中能生成带验收条件的任务；固定顺序策略无法表达这些状态条件。当前 Qwen 仍容易把所有场景套入默认 S1–S4 工具链，因此“证据充分停止”“来源冲突先核验”和“补查前先建立证据基线”需要加入更强的场景状态约束。

本结果不支持宣称 Qwen 已经稳定完成动态决策，但证明 V3 场景能够暴露 V1/V2 中看不到的问题：连续重复反证检索、忽略冲突状态、无必要继续搜索以及补查任务时序不合理。
