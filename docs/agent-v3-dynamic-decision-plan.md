# Agent V3：动态决策压力测试与案例升级

## V3 研究问题

V3 不再把“完成固定工具链”作为主要问题，而是检验 Agent 在证据状态变化时能否选择不同的下一步：空结果改写查询、来源冲突先核验、支持材料后主动找反证、证据充分时停止、截点泄漏时隔离、信息不可得时生成补查。

## 针对 V2 六个问题的改进

1. **任务过于规则化**：新增 6 类动态分支场景，每个案例均包含空结果、来源冲突、竞争性假设、充分证据停止、未来材料和补查缺口；每个任务冻结初始状态和预期下一步。
2. **工具反馈太浅**：工具返回证据状态、来源族、冲突字段、重复候选、截点泄漏标记、信息缺口和候选动作理由，允许 Agent 做状态条件决策。
3. **案例缺少动态压力**：候选案例中优先加入“支持与反证并存、调查升级/降级、召回处置与调查材料并列、调查结论留出”的案例。当前本地候选中优先级为：EA22002（Tesla Autopilot，电气/驾驶辅助，跨阶段材料）、PE20016（Chevrolet Bolt EV 电池起火，独立事件与召回材料并存）、PE23015（Ford EcoSport 油泵失效，发动机失效与投诉文本可区分）、RQ23004（Mustang Mach-E 高压电池接触器，召回处置和投诉关联）、PE24004（Honda Ridgeline 后视摄像头，部件明确且可检验反证）。这些候选需按截点前材料、投诉记录和留出结案答案再次核验；不以投诉量单独替换 EA23003。
4. **评分偏向工具覆盖**：主指标改为四维决策价值：安全与可追溯性 30%、目标覆盖 25%、证据质量 20%、下一步价值 25%。工具数量、延迟和 token 只作为成本诊断。
5. **验证器压制动态性**：固定流程只作为主对照，确定性工具循环降为消融；完成门槛只阻止不安全或明显不满足目标的停止，不强制执行全部工具。记录模型自主动作和验证器纠偏动作的区别。
6. **没有单独测量动态优势**：新增动作分歧率、状态条件正确率、空结果恢复率、冲突处理正确率、反证发现率、留出答案命中率和安全停止率。

## V3 数据集

`scripts/build_v3_dynamic_benchmark.py` 生成 11 个现有案例 × 6 个动态场景，共 66 条任务。每条任务包含 `initial_state`、`gold_next_action`、`scenario` 和案例截点。V3 还应从优先候选中选出至少 2 个高动态案例，扩展到每案 3 个截点，并加入后续结案材料作为 holdout。

## 主要比较

固定流程、普通 RAG、主动调查 Agent 是课程要求的三种主结果。确定性工具循环只做消融，用来判断 Agent 的收益是否来自动态选择而不是循环结构。每种策略在相同初始状态、资料截点和动作预算下运行。

## 验收标准

V3 首先完成离线 66 条动态任务，再选主案和两个高动态迁移案例运行 API。报告必须同时给出总体分数和动态压力测试分数，不能用总体平均掩盖空结果、冲突和截点泄漏场景的失败。
