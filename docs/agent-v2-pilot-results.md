# Agent V2 迭代验证记录

## 离线 pilot

在 22 条代表性最新截点任务上，V2 的用户价值分数均值为 **90.91/100**，ReAct 为 **80.91/100**。两者的安全、目标覆盖和调用效率接近，差异主要出现在“下一步价值”：V2 能在反证目标中主动使用替代解释检索，在补查目标中生成带证据 ID 的补查任务；ReAct 的固定顺序策略不会根据目标切换查询。

## Qwen API 代表任务

- EA23003 counterevidence：V2 得分 **93.34/100**。Qwen 选择了替代解释检索和实体关联；没有截点或来源错误。
- 首次 EA23003 followup：模型曾在没有证据台账时直接创建补查任务，随后重复创建补查任务。该样例暴露了“补查前证据基线不足”和“语义重复任务”问题。
- 随后加入完成门槛和重复补查拦截，要求先尝试证据检索，并阻止已有待确认任务的重复创建。

上述 API 结果是代表性调试样例，不替代 88 条全量结果。完整 API 重跑应在 V2 代码冻结后进行。

## 暴露出的剩余问题

1. 模型可能忽略候选动作的 utility，仍需记录模型选择与候选最优动作的一致率。
2. 仅用动作签名去重不足以识别语义重复补查，已加入按工具类型和状态的补查门控；后续可加入问题文本相似度阈值。
3. `needs_human_review` 仍可能是安全停止的合理结果，不能简单按失败统计。
4. 下一轮需要把 V2 分数、门控触发次数、重复动作次数和模型重试次数一起报告。
