# 当前版本实验总结与问题记录（V1）

## 版本冻结

V1 是扩展研究数据上的单 Agent API 实验版本。任务集合为 11 个公开案例、每案 1 个最新历史截点、每案 8 个调查目标，共 88 条任务。四种策略使用同一案例快照和截点：固定流程、普通 RAG、ReAct（确定性 OfflinePolicy 工具循环）和 Qwen API 主动调查 Agent。运行保持并发 1，模型通过 OpenAI-compatible API 接入。

基线文件：`outputs/evaluations/eval-research_api-88-resumable.json`；优化后协议兼容版：`outputs/evaluations/eval-research_api-88-optimized.json`。本记录把优化版作为 V1 的最终冻结结果，协议修复前的结果仍保留作迭代证据。

## V1 结果

- 88/88 条任务自动验收通过；优化版 79 条 `completed`、9 条 `needs_human_review`。
- Agent 自动轨迹分数均值 3.193/5；固定流程 3.125/5；普通 RAG 2.125/5；ReAct 3.250/5。
- Agent 平均延迟约 50.33 秒，平均 token 约 24,830。
- `before` 日期别名归一化后错误归零；模型动作格式仍出现有界重试，但没有导致任务 `passed=false`。

## V1 的有效成果

1. 截点过滤、来源元数据、证据账本、状态快照和 JSONL 轨迹已经贯通。
2. 88 条任务能够在共享 API 上串行完成，工具失败和模型协议失败不会无限重试。
3. Agent 能在同一工具集合内完成投诉筛查、趋势分析、证据检索、实体关联和补查任务。
4. 结果可以与固定流程、普通 RAG 和 ReAct 复现比较。

## V1 问题

1. **评价指标偏向流程覆盖。** 主要奖励是否调用期望工具，不能充分衡量下一步是否真正减少关键不确定性、是否选择了更有价值的查询。
2. **ReAct 对照不完全同质。** ReAct 是确定性 OfflinePolicy，主动 Agent 是远程 Qwen；ReAct 没有模型格式错误和网络延迟风险，因此分数略高不能解释为调查智能更强。
3. **Agent 的计划较静态。** 固定的 S1–S4 计划没有显式表示竞争性假设、信息缺口和每个动作的验收条件，模型容易提前 `done`。
4. **反证和补查没有形成硬门槛。** `counterevidence` 与 `followup` 任务中，模型可能在证据检索后结束，导致反证查询或可执行补查不足。
5. **证据质量指标不足。** 当前引用可核验主要检查日期、来源 URL 和记录 ID；没有充分区分独立来源族、支持与反对证据平衡、重复来源和证据对假设的区分能力。
6. **质量与成本曾混在一起。** V1/V2 曾将工具调用效率放入质量分，但工具数量不能代表调查价值；后续版本将调用数、延迟和 token 单独作为成本诊断。
7. **“通过”与“调查质量”混淆风险。** `passed=true` 说明结构和引用检查通过，不代表调查结论语义正确，也不代表真实企业效率提升。
8. **模型协议仍有重试开销。** JSON 片段提取和参数别名修复降低了失败影响，但非法动作类型仍会消耗重试预算和延迟。
9. **成本收益尚未量化。** V1 记录了延迟和 token，但没有把额外调用成本与新增证据、减少重复、发现反证联系起来。

## 迭代报告应回答的问题

下一版本需要回答：主动 Agent 是否在相同证据预算下提高调查价值；是否比 ReAct 更能根据目标切换查询策略；是否减少确认偏差；主动决策增加的模型成本是否值得；在空结果、来源冲突和未来材料等异常输入下是否保持安全停止。
