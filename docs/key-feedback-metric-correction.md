# 关键实验评分校正说明

原始文件 `key-incomplete-feedback-comparison.json` 中的 0%/100% 不能作为性能结论。原因有三点：

1. 只有 4 个案例，二元比例的最小步长是 25%；四案全中或全不中时必然显示 0% 或 100%。
2. 原脚本把固定流程、普通 RAG 和确定性工具循环的 `decision_correct` 直接写成 0，把 Agent 的成功定义为几个关键词同时出现。基线没有获得同等的结构化输出机会，评分存在偏置。
3. “完整决策正确”把方向、机制、处置压成一个布尔值，无法显示部分成功，也没有报告不确定性区间。

因此原始 0%/100% 结果已降级为运行轨迹，不纳入最终结论。

校正文件：[key-incomplete-feedback-calibrated.json](../outputs/evaluations/key-incomplete-feedback-calibrated.json)。每个案例按六个可观察子能力计分：新证据发现、引用有效、方向更新、保留机制不确定性、提出可执行补查、不过度断言。总分是描述性分数，Wilson 区间仅作为小样本不确定性提示，不能作为显著性检验。

| 方法 | 得分 | 组件总分 | 近似95%区间 |
|---|---:|---:|---:|
| 固定流程 | 0.500 | 12/24 | 0.314–0.686 |
| 普通 RAG | 0.500 | 12/24 | 0.314–0.686 |
| 确定性工具循环 | 0.500 | 12/24 | 0.314–0.686 |
| 主动调查 Agent | 0.875 | 21/24 | 0.690–0.957 |

四个案例中，所有方法都能发现新增材料并通过来源检查；Agent 额外完成了方向更新、不确定性保留和补查建议，但其中部分组件在 3/4 案例满足。因此当前结果只能说明 Agent 在这个小型、预设的反馈场景中展现出更完整的调查输出，不能推出普遍优于基线。

下一步应把反馈场景扩展为不完整、冲突、错误来源、空结果和材料延迟等多种条件，并预先冻结各方法的统一结构化输出格式；至少达到 20 个独立任务后，再报告点估计和区间。
