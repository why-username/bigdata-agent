# Agent V4：动态状态对照实验

## V3 的实验缺口

V3 运行器只执行了 Qwen 主动调查 Agent，虽然包含 4 个案例和 6 类动态场景，但没有在相同初始状态下运行固定流程、普通 RAG 和确定性工具循环。因此 V3 只能分析 Agent 的动态行为，不能回答 Agent 是否优于其他解决方式。

V4 将四种方法放在同一任务、同一案例、同一截点和同一动态状态下比较：

1. 固定流程：按固定步骤执行；
2. 普通 RAG：一次证据检索；
3. 确定性工具循环：作为消融基线，按规则顺序行动；
4. Qwen 主动调查 Agent：读取动态状态并选择下一步。

## V3 问题的改进

- 证据充分停止：状态中明确 `sufficient_evidence=true`，主策略必须把停止作为候选动作；
- 反证后重复检索：保存查询语义指纹，重复或相似查询必须转向实体核验、补查或停止；
- 补查时序：补查场景明确 `individual_data_missing=true`，优先创建补查任务；
- 来源冲突：明确 `source_conflict=true`，优先执行实体/来源核验；
- 同初始状态：所有方法读取同一场景状态，避免 Agent 看到额外信息；
- 结果分层：分别报告主指标、动态分支指标、安全指标和成本诊断。

## V4 动态指标

- 状态条件首步正确率：第一步是否符合场景的预注册动作集合；
- 反证转向率：反证检索后是否避免相似查询并选择新证据族、实体核验或安全停止；
- 充分证据停止率：证据足够时是否在预算内停止；
- 补查时序正确率：信息缺失时是否先生成可验收补查；
- 冲突处理率：来源冲突时是否先核验而不是直接总结；
- 留出结论命中率：是否发现 holdout 中的后续结论；
- 安全通过率：无截点泄漏、无无来源主张、无无限循环。

工具调用数、延迟和 token 仍是成本诊断，不进入质量分。

## 研究计划进度更新

- 阶段 1：案例和数据截点，已完成；EA23003 主案和 4 个动态候选包已冻结。
- 阶段 2：清洗、规范化和索引，已完成；投诉、调查材料、召回材料和来源哈希已保存。
- 阶段 3：工具、固定流程和普通 RAG，已完成；统一结构化返回、截点验证和错误记录已接入。
- 阶段 4：Agent、状态和边界，已完成 V2；V4 新增动态状态反馈和显式安全门。
- 阶段 5：测试和验收，V1/V2 已完成 88 条 API；V3 已完成 24 条动态 API pilot；V4 正在完成四方法动态对照。
- 阶段 6：最终报告、PPT 和 Demo，尚未开始，需要等待 V4 对照结果冻结。

研究计划需要更新两点：确定性工具循环从主比较降为消融基线；V4 动态场景和安全门成为主动 Agent 的核心实验，主结果必须同时报告 Agent 自主动作和安全门纠偏动作。
